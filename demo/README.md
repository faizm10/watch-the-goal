# Demo footage

Everything here is generated by [`scripts/make_demo.py`](../scripts/make_demo.py)
from a fixed seed. No real people or recordings are involved, so you can
redistribute the output. The rendered videos are git-ignored. Regenerate them
with:

```sh
uv run python scripts/make_demo.py          # writes demo/footage/, ~2 min
uv run watch-the-goal demo/footage          # opens the app with all four imported
```

| File | Stands in for | Format |
| --- | --- | --- |
| `sunday_match_wide.mp4` | the tripod on the touchline, whole match | 6 min, 1280×720, 25 fps, H.264, audio |
| `phone_goal_portrait.mov` | someone filming goal 2 upright | 540×960 shown, stored sideways with rotation metadata (like iPhones do), HEVC, audio |
| `phone_goal_60fps.mp4` | someone filming goal 3 in 60 fps | 1920×1080, 60 fps, H.264, audio |
| `phone_chance_noaudio.mp4` | a clip with the mic muted | 1280×720, 30 fps, H.264, **no audio track** |

`labels.json` is the ground truth: goals at 70 s, 176 s and 296 s, each built
as *turnover (t−9 s) → run → assist (t−4.2 s) → shot (t−1 s) → goal → cheer*.
Two decoys test false positives: a loud argument at 128 s with no goal, and a
shot that goes wide at 236 s. `goal_areas` holds the goal boxes as the UI
would store them.

Use `--quick` for half-size frames (that's what CI uses).

## Assist-to-group-chat demo

The local deliverable `demo/assist-to-group-chat.mp4` is a 20-second,
1280×720 capture of the editor followed by the scored export. Like the
generated footage it is git-ignored. For the recording, a fresh workspace used
a two-second detection lead-in. The detector selected 67.50–75.25 around the
first goal. Dragging the start to 63.00 recovered the pass at 65.80. Blue,
Red and the 1–0 score were entered for this recording. The last nine seconds
show the export with its original synthetic match audio.
