# Contributing

Thanks for helping. Watch the Goal is small on purpose: one Python package, a
standard-library web server, and a vanilla JS page with no build step.

## Setup

You need Python 3.10+, FFmpeg (with `ffprobe`) on your PATH, and
[uv](https://docs.astral.sh/uv/).

```sh
uv sync                         # creates .venv with numpy, OpenCV (headless) + pytest
uv run pytest -q                # ~10 s, builds its own tiny fixture videos
uv run watch-the-goal --workspace /tmp/wtg-dev
```

Set `WTG_DEBUG=1` to log HTTP requests and full tracebacks from background jobs.

## Layout

| Path | What it does |
| --- | --- |
| `watch_the_goal/media.py` | ffprobe/ffmpeg wrappers: probe, frame grab, preview proxy |
| `watch_the_goal/signals.py` | streams audio loudness and motion out of a video |
| `watch_the_goal/detect.py` | turns signals into explained candidate moments, ranks them, applies player evidence (pure numpy) |
| `watch_the_goal/pipeline.py` | long-recording analysis: signals → candidates → optional player detector → ranked suggestions, debug overlays |
| `watch_the_goal/vision/` | OpenCV frame sampling, the `none`/`yolox`/`rfdetr-nano` person detectors, player counts near goals, model downloads, overlays |
| `watch_the_goal/review.py` | opt-in AI review through a local Ollama vision model: windows, validation, reranking, suggested trims, fallbacks |
| `watch_the_goal/project.py` | sources, clips, reel order; saved as `project.json` |
| `watch_the_goal/export.py` | per-clip normalisation (rotation, size, fps, audio), recap captions and fades, and concat |
| `watch_the_goal/writer.py` | reel titles, captions and end cards from tags and detection, or optionally from Claude, OpenAI or Gemini (text only, `ai` extra) |
| `watch_the_goal/app.py` | services shared by the server and the CLI; background jobs |
| `watch_the_goal/server.py` | JSON API and static files, with Range support for `<video>` |
| `watch_the_goal/static/` | the UI |
| `scripts/make_demo.py` | renders the synthetic demo match and phone clips |
| `scripts/eval_detection.py` | scores detection against labelled goal times |
| `scripts/eval_highlights.py` | scores suggestions per detector, with and without AI review (goals, buildup, false suggestions, time) |
| `scripts/label_people.py`, `scripts/bench_detectors.py` | label people in frames; person-detector recall, false positives, speed |
| `scripts/eval_tracking.py` | ByteTrack vs. no tracking, in a throwaway environment |
| `scripts/e2e_ui.py`, `scripts/check_reel.py` | Playwright run through the real UI; checks an exported reel against its project |
| `.agents/skills/`, `.claude/skills/` | agent skills (identical copies, `tests/test_skills.py` keeps them in sync) |

## Ground rules

- **Never modify source footage.** Files imported by path are only read.
  Uploads are copied into the workspace.
- **No invented numbers.** Suggestions carry reasons, not confidence scores.
  If you add a signal, add a plain-language reason for it.
- **No footage in Git.** `.gitignore` blocks common video extensions. Fixtures
  are generated by code (`tests/conftest.py`, `scripts/make_demo.py`). Only
  add a real recording to the docs or tests if everyone in it has cleared it
  for redistribution, and keep it out of the repo even then. Link to it instead.
- **Keep it local.** No accounts, uploads, API keys, telemetry or GPU
  requirements in the default path. The optional caption writer may send
  text, never footage, to a provider the user picks with their own key. Models are downloaded only when asked,
  from pinned revisions with checksums. AI review only talks to loopback
  addresses.
- **Optional means optional.** Analysis must work with no model downloaded
  and no reviewer running; every failure falls back to the baseline and says
  why. The user's edits always win over automatic suggestions.
- **Record what you add.** Any new dependency, checkpoint or borrowed text
  goes in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) with version,
  source and license.

## Changing detection

1. Add or change a signal in `signals.py`, or the logic in `detect.py`.
2. Add a unit test in `tests/test_detect.py` using hand-built `Signals` arrays.
3. Run the evaluation on the demo match, and on any labelled real footage you
   have, and paste both results in your PR:

   ```sh
   uv run python scripts/make_demo.py            # once, ~2 min
   uv run python scripts/eval_highlights.py demo/footage/labels.json demo/footage/labels_goal_areas.json --out bench/synthetic
   uv run python scripts/eval_highlights.py path/to/your.labels.json --out bench/real [--review]
   ```

   Report synthetic and real results separately. The synthetic match is easy
   by design; it proves the mechanics, not the quality. The `soccer-vision`
   skill (`.agents/skills/soccer-vision/SKILL.md`) walks through labelling and
   the detector benchmark; [docs/BENCHMARKS.md](docs/BENCHMARKS.md) has the
   current numbers to beat.
4. UI changes: run `uv run --group e2e python scripts/e2e_ui.py` (see the
   `webapp-testing` skill) and attach its screenshots.

See [docs/DETECTION.md](docs/DETECTION.md) for ideas.

## Pull requests

- Keep PRs focused; describe what you tested (OS, FFmpeg version, footage type).
- `uv run pytest -q` must pass. CI runs it on Ubuntu and macOS.
- UI changes: include a screenshot or a short clip.

For timeline or recap changes, run the landscape and portrait commands in the
webapp-testing skill. The script writes screenshots and pairs of browser and
export frames, checks source audio against the MP4 and reports inconclusive
edges. Both agent skill directories should contain the same commands.
